# 2026-06-09 工作日志

## 修复文字模式下属性面板不生效

**问题**：文字模式下，右侧属性面板修改字号、颜色、描边、不透明度全部无效。

**根因分析**（三个 Bug 叠加）：
1. `TextModule.getPropertyPanelHTML()` 用 `id` 标识控件（如 `id="prop-font-size"`），但 `PropertyPanel._handleInput()` 通过 `target.dataset.prop` 识别控件 → `data-prop` 为空 → 在第 148 行直接 `return`，所有修改事件被忽略
2. `PropertyPanel._handleInput()` switch 缺少 `stroke` case
3. `TextModule.onPropertyChange()` switch 用 `'font-size'`（连字符），但 `_handleInput` 传的是 `'fontSize'`（驼峰），不匹配

**修复**：
- `TextModule.js`：属性面板 HTML 中 `id="prop-*"` → `data-prop="*"`；`onPropertyChange` 中 `'font-size'` → `'fontSize'`
- `PropertyPanel.js`：`_handleInput` switch 新增 `case 'stroke': active.set('stroke', value);`

涉及文件：`src/modules/TextModule.js`、`src/ui/PropertyPanel.js`

## 属性面板改进

### 1. 不透明度滑块缩窄
`.property-range` 从 `flex: 1` 改为固定 `width: 90px; flex: 0 0 auto`。涉及文件：`style.css`

### 2. 不透明度双重除法修复
**问题**：不透明度 90% 文字直接消失（100% 正常）。
**根因**：`_handleInput` case 'opacity' 中 `value` 已变为 0.9，之后 `onPropertyChange` 用 `parseInt(value)/100` = `parseInt(0.9)/100` = `0/100` = 0 → 覆盖为透明。
**修复**：用 `target.value`（滑块原始值）传给 `onPropertyChange`。涉及文件：`PropertyPanel.js`

## 修复裁切操作无法撤销

**问题**：裁切后按 Ctrl+Z 无法恢复。

**根因**：`canvas.clipPath` 是画布级别的属性。Fabric.js 的 `canvas.toJSON()` 只序列化画布上的物件，不序列化 `canvas.clipPath`。`HistoryManager.saveState()` 生成的快照中不包含 clipPath → 撤销恢复时 clipPath 丢失 → 裁剪效果在视觉上仍然存在。

**修复**：
- `CanvasManager.toJSON()`：手动将 `canvas.clipPath` 序列化为 `json._canvasClipPath`
- `CanvasManager.fromJSON()`：用 `fabric.util.enlivenObjects` 恢复 `canvas.clipPath`；当快照中无 `_canvasClipPath` 时显式清除 `canvas.clipPath = null`（第一次修复合入后仍不生效的原因：只处理了"有 clipPath"的分支，`else` 分支缺失导致撤销时 clipPath 残留）

涉及文件：`src/core/CanvasManager.js`（两次修复）

## 修复文件匹配无法加载图片（两轮）

**问题**：通过文件匹配进入插件后图片不显示。

**第一轮修复**（type 值 + 重复进入）：
- `preload.js`：同时处理 `'file'`/`'files'`；`payload` 兼容非数组；try-catch
- `index.js`：`onPluginEnter` 检测 `window.__imageSource` 并调用 `_loadImage()`

**用户反馈**："依旧没有" → 第一轮修复不够

**第二轮根因分析**：仅依赖 `window.__imageSource` 不够可靠。核心问题是 page context 的 `onPluginEnter` handler 依赖 preload context 设置的 `window.__imageSource`，存在两个潜在问题：
1. 两个 context 的 handler 执行顺序不确定（竞态）
2. `window.__imageSource` 可能是 `null`（preload `readImageFile` 出错时静默吞掉）

**最终修复**：`index.js` 的 `onPluginEnter` **直接处理 payload**，彻底不依赖 `window.__imageSource`：
- file/files 类型：调用 `window.readImageFile(fileInfo.path)` 直接读取文件
- img 类型：仍用 `window.__imageSource`（剪贴板 API 只能在 preload 中使用）
- 添加 console.log 排查日志
- `_checkExternalSource` 添加超时日志

涉及文件：`preload.js`、`src/index.js`、`AGENTS.md`
